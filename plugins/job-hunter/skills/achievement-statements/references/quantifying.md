# Finding numbers

Use when a bullet that matters for the target role has no outcome or number. Ask the user. Only the user supplies numbers; you only help them find and phrase them.

Adapted from `resume-quantifier` in [ResumeSkills](https://github.com/Paramchoudhary/ResumeSkills), MIT License, Copyright (c) 2026 Resume Skills.

## Kinds of number

| Kind | Examples |
|---|---|
| Money | Budget managed, cost saved, revenue or funding won |
| Time | Hours saved, turnaround cut, delivered ahead of a deadline |
| Percentage | Growth, error rate down, conversion up, test coverage |
| Volume | Users, customers, tickets, records, pages, components, team size |
| Quality | Satisfaction score, accuracy, grade, uptime, accessibility audit result |
| Frequency | Per day, per week, per release, per semester |
| Performance | Latency or load time before → after, requests or jobs handled, build or deploy time, bundle size, cloud cost |

## Questions to ask

Pick one or two. Do not run the whole list.

- **Scale:** How many people, users, items or projects? How big was the team?
- **Change:** What was different afterwards? What would have happened without you?
- **Before and after:** What was it like before? What was it after?
- **Comparison:** How did it compare with the target, the previous version, or the rest of the team?

## When the user says "I have no numbers"

| Situation | Try counting |
|---|---|
| "I was one person in a team" | Your part: features, screens, endpoints, tests or pages you built |
| "I can't see business results" | The work itself: tickets closed, reports produced, components shipped |
| "My work had no measurable outcome" | Who used it and how often: "used by 12 tutors each week" |
| "The results are confidential" | A percentage instead of a dollar figure, or leave the number out |
| "I was junior" | Volume and accuracy: "processed 200 records a day with no errors found in audit" |

## Estimates

Only from the user's own recollection, and only with their agreement:

- **Lower bound.** They recall "about 120" → "100+". Round down, not up.
- **Frequency × time.** They recall "around 5 a week for 8 months" → "150+".

Record every estimate in `resume/master-resume.md` as an estimate, with how it was worked out, so the user can explain it at interview.

## Do not

- Guess or derive a number from figures the user did not give.
- Write a projected or expected result as achieved. Write "designed to…" or leave it out.
- Claim a team result as the user's own ("reduced churn 20%" when the team did).
- Use a number the user could not explain in an interview.
- Put more than two numbers in one bullet.
- Force a number into every bullet. Task + purpose is fine when nothing is measurable.
