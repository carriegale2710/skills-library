# Achievement statements

## Formula

**Action verb + task + outcome or purpose**, with a number only when the number adds value.

- Task only (weak): "Built UI components"
- Task + outcome: "Built a reusable React component library, cutting new-page build time from 3 days to 1"
- Task + purpose (when no outcome is measurable): "Wrote end-to-end tests for checkout to catch payment regressions before release"

Not every bullet needs an outcome or a number. Do not force one that does not read naturally. Never invent one.

## Rules

1. Start every bullet with a strong past-tense action verb. Use present tense only for a current role, and keep it consistent within that role. Pick verbs from `references/action-verbs.md` that signal the skill the job ad wants.
2. One sentence per bullet. Aim for one line.
3. Put keywords from `criteria.md` into bullets where they are true. To reword a true fact in the employer's terms, use the strategies in `references/reframing.md`. Do not repeat a keyword just to raise the count.
4. Order bullets within a role by relevance to the target job, not by time.
5. 3-6 bullets per role. Fewer for unrelated roles.
6. Prefer the activities and achievements that set the user apart from other graduates with similar backgrounds. Avoid generalities.
7. Use the same formula for work, academic achievements, projects and extracurricular involvement.

## Rewrite these patterns

| Pattern | Problem | Fix |
|---|---|---|
| "Responsible for…", "Duties included…" | Describes the job, not what you did | Start with the verb for what you did |
| "Demonstrated leadership through training…" | Padded opener, says the skill twice | "Trained…" |
| "Dealt with complaints", "Handled difficult…" | Negative tone | "Resolved customer issues…" |
| "Helped with…", "Assisted in…" (when you led it) | Undersells | Use the verb for your actual part |
| "Worked on…", "Was involved in…" | Vague | Name the task |

## Process

For each master-resume entry:
1. Read the raw task, outcome and metric.
2. Draft the bullet with the formula.
3. If the outcome is missing and the task matters for the target role, ask the user one question: "What changed because of this?" or "Roughly how many/much?" If they say they have no numbers, use `references/quantifying.md`.
4. Present the bullets. Mark any you could not quantify so the user can decide.
